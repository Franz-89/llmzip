How a trace flows from the moment it's opened to the moment it's archived — and why most of that happens on its own, so the board stays clean without anyone tidying it.

New to Trace? See Trace — Overview & how to use it for the basics first.

The five statuses

Every trace is in exactly one status. The first four are the columns on the board; the fifth is the archive.

  • Open — logged, not yet started.
  • In Progress — someone is working it.
  • Waiting — paused, waiting on something outside (a part, a reply).
  • Resolved — the work is done, but it's still on the board for a short while.
  • Closed — archived. Off the board, but always findable.

You move a trace along either by dragging it between columns or by changing the status in its detail view.

Reaching "Resolved"

There are two ways a trace becomes Resolved:

  • Mark the solution. In the Timeline, mark the message that explains the fix as the solution — the trace moves to Resolved automatically. This is the recommended way: it resolves and records how you fixed it.
  • Move it yourself — drag it to Resolved, or set the status directly.

It won't resolve while something is open. If the trace still has open sub-tasks or blockers, it can't be resolved yet. Marking the solution still records it — the trace resolves on its own once those are done. (See Trace — Sub-tasks & dependencies.)

The grace period, and automatic closing

A resolved trace does not disappear straight away. It stays in the Resolved column for a grace period, so it can be checked, and so it's easy to reopen if the fix doesn't hold. After that period, the system closes it automatically — it leaves the board and becomes archived.

Why a grace period? A machine that's "fixed" but breaks again two days later was never really fixed. Keeping resolved traces visible for a while — then archiving them on their own — means the board stays tidy without anyone doing housekeeping, and genuine fixes get a chance to prove themselves before they vanish.

Nothing is ever lost. Closed traces leave the board but stay fully searchable in the List / Archive view — see Trace — Finding traces. You almost never need to close a trace by hand; the system does it for you.

Reopening — when it comes back

If a problem returns, don't open a brand-new trace for it — find the resolved or closed one and use Reopen. It goes back to Open, ready to be worked again, with all its previous history intact.

Reopens are counted — on purpose. A trace that's been reopened shows a ↻ ×n marker. A high count is a useful warning sign: a recurring, never-quite-fixed problem — exactly the kind of thing worth a closer look, or a bigger decision about the machine.

The "Waiting" detour

At any point before it's done, a trace can sit in Waiting — paused on the outside world. Record what you're waiting for; when it arrives, mark it arrived and the trace moves back into progress. Waiting keeps a stalled trace honest: it's clearly "blocked on something", not forgotten.

The whole cycle at a glance

  1. Open → In Progress — pick it up and work it.
  2. Waiting — if you're stuck waiting on something (optional detour).
  3. Resolved — mark the solution; it stays on the board through the grace period.
  4. Closed — archived automatically after the grace period; still findable.
  5. Reopen — any time it comes back; the count goes up.
