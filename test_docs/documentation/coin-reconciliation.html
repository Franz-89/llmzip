Check that the cash counted at collection matches what the machine actually took in — three independent figures, side by side, per collection.

Introduction

The Coin Reconciliation report answers the question every operator eventually asks: did the cash we counted match what the machine says it received? For each confirmed collection it puts three numbers next to each other so a discrepancy has nowhere to hide.

The three figures:

  • Expected — what the machine's mechanical counter says should be there (the counter reading, converted to cash).
  • Cash — what was physically counted at collection.
  • Coin-in — what the electronic coin log recorded, for that exact collection.

Three independent sources for the same money. When they agree, the collection is clean. When they don't, the gaps tell you what kind of problem you have.

The collection window — why the timing is exact

The clever part is which coins belong to a collection. A collection's counter is confirmed at a precise moment. The coins that belong to it are the ones logged between the previous collection's confirmation and this one's — nothing before, nothing after.

It follows the counter, not the cash count. Even if the cash is counted days later, the coins that belong to a collection are the ones that were in the box when the counter was read. This makes the match exact, with no guesswork about which day a coin "counts" for.

Reading the deltas

The report colours the differences so problems stand out. The one to watch is Cash vs Log:

  • Cash below the log (red) — less cash was counted than the machine says it received. This is the money-missing signal — the sharpest one on the report.
  • Cash above the log (green) — more cash than logged, usually harmless (for example, coins whose value wasn't yet configured).

A second delta, Log vs Counter, compares the electronic log against the mechanical meter — useful for spotting a counter or acceptor that has drifted.

Biggest shortfalls

Machines are ranked by how far their counted cash falls below their log, so a persistent problem rises to the top. A single bad collection can be a miscount; the same machine appearing again and again is worth investigating.

Unpriced coins are excluded from the ranking. A collection whose coins were all logged before the machine's values were configured shows a €0 log — not because cash is missing, but because those coins have no known value. The report marks these and keeps them out of the shortfall ranking, so a data gap never masquerades as theft.

Only confirmed collections

A collection has to be confirmed to be reconciled. The confirmation instant is what defines the collection window, so pending collections don't appear here. If a collection you expect is missing, check that its counter has been confirmed.

Use it after every collection cycle. Run the report over the period you just collected, scan the Cash-vs-Log column for red, and you have an honest, three-way check on the count — without opening a single collection by hand.
